# UX review of the phase 13 screenshots

Source: `tests/Tempo.Blazor.E2E/__screenshots__/data-table-redesign/{light,dark,indigo}/` (23 PNG per theme, element shots,
generated by `DataTableRedesignBaselineScreenshots` with `TM_WRITE_BASELINES=1`). The dark and indigo sets were reviewed by
two independent reviewers who opened every file; the light set was opened by the implementer. Every shot is taken only
after the state it names has been asserted in the DOM. Each file shows what its name claims.

## Verified OK

Toolbar buttons are equal height in the Card table (`desktop-1440-table-card`); the export menu shows All rows (n) /
Selected rows (m) with the empty-selection explanation; the column menu opens anchored to its kebab; the Views panel opens
directly under its trigger; filter, views and save-view sheets are exactly 390px wide; the long view name ends in an ellipsis;
the pinned column sits on the right under `dir=rtl`; focus rings are visible on the grid cell and the radiogroup in all three
themes; dark surfaces use dark tokens (no light-theme colours).

## Fixed in fix round 1 (CSS guards in `DataTableUxDefectsCssTests`, baselines regenerated)

1. **RTL header:** `[dir="rtl"]` cells and headers follow the writing direction (an explicit Align class still wins) and a
   pinned header reserves the pin glyph with `padding-inline-start/end` — the glyph no longer overlaps the first letter.
2. **Scroll layout / filter:** the filter input and its placeholder end in an ellipsis (`overflow: hidden; text-overflow:
   ellipsis; white-space: nowrap`); Scroll cells already clip with an ellipsis in a narrow container, now capped at
   `max-inline-size: 60cqi` so one unbroken value cannot widen the table.
3. **Touch targets:** inside `.tm-overlay-panel-sheet` the filter inputs/selects/clear, the view rows and their buttons and the
   footer buttons are at least `var(--tm-touch-target)` tall, with a gap between neighbours. The filter sheet shows one "Done"
   (the footer's is hidden inside a sheet; the popover keeps it).
4. **Cards hint:** "Drag column headers here to group" is hidden in a narrow Cards table (the hint lives in `TmDataTable`;
   `TmMultiViewList` has no such text).

## Fixed in fix round 2

1. **Hardcoded size:** the RTL pinned-header padding and the pin button now share `--tm-data-table-pin-glyph` / `--tm-data-table-pin-inset` (tokens.css) instead of `1.1rem` / `6px`.
2. **RTL edge header:** investigated - pinned offsets already use `inset-inline-start/end` (`--tm-pin-left/right`), so the pin sticks to the RTL start edge. The cut `COLUMN 10` was ordinary scroll overflow of the 15-column table (the viewport ends mid-column at the scroller's left edge), not a clipped header. The baseline now scrolls to the scroll end so its edges fall on whole columns; no further CSS change needed.

## Fixed in the cleanup round (post-phase 14)

1. **RTL pin glyph:** the pin button's glyph is mirrored with `transform: scaleX(-1)` under
   `[dir="rtl"]` (`DataTableUxDefectsCssTests.Rtl_PinGlyph_IsMirrored`) and the RTL plain-cell
   rule now says `text-align: start` instead of a hard-coded `right`.
2. **"All" in select filters:** the blank option of a `FilterType.Select` / `Boolean` column
   filter is a localized "All" (`TmDataTable_FilterAll`, en/cs/sk/fr) instead of an unlabeled
   empty option — the demo's Department filter gets this for free.
3. **Loading no longer shifts column widths:** the loading state renders four skeleton rows with
   ONE CELL PER COLUMN (same classes and inline widths as data rows) instead of a single colspan
   spinner cell, so the auto table layout measures the same columns before and after the data
   arrives (`TmDataTableBasicTests.TmDataTable_Loading_ShowsSkeletonRows_WithOneCellPerColumn`).
4. **Duplicate count dropped:** `TmMultiViewList` hides the "Items: N" readout while the filter
   builder's result preview is showing the same number for active filters
   (`ItemCount_StepsAsideWhileTheFilterResultPreviewShowsTheSameCount`).
5. **Empty-cards text centred:** the empty-state cell carries `.tm-data-table-empty-cell` and the
   cards container rule turns off the card cell's space-between row layout, centring the text
   like every other empty state (`CardsMode_EmptyStateCell_IsCentred`).

## Fixed in fix round 3 (the last "Open" items + the two red E2E specs)

1. **Cards mode checkbox row:** the row checkbox no longer spends a whole card row on itself —
   it docks into the card's inline-end corner (`position: absolute` + the touch-target box) and
   the Title cell reserves that corner with `padding-inline-end`
   (`DataTableUxDefectsCssTests.CardsCheckbox_DocksIntoTheCardCorner_InsteadOfItsOwnRow`,
   `CardsTitle_ReservesTheCheckboxCorner`).
2. **Native white checkboxes in dark:** the portaled chrome's radios/checkboxes (view dialog,
   view-panel columns, column picker) share one `accent-color: var(--tm-color-primary)` rule, so
   no native control renders unthemed in dark (`PortaledCheckboxes_FollowTheThemeAccent`).
3. **Bare empty states:** the DataTable and MultiViewList empty states render with an icon and a
   localized supporting line (`TmDataTable_EmptyDescription`, en/cs/sk/fr + MockTmLocalizer);
   `TmDataTable_Empty_Items_ShowsIconAndLocalizedDescription`.
4. **Views button height:** the Views toggle (a full-height `.tm-btn`) and the content-height
   view-switcher buttons next to it now share `var(--tm-input-height-sm)` in the list toolbar
   (`MvlToolbar_ViewsToggleMatchesItsNeighbours`).
5. **`edge-fifteen-columns` shows 10 of 15:** the capture scrolls the 15-column scroller to its
   end and writes a second baseline, `edge-fifteen-columns-end` — between the two shots the
   baseline demonstrates the whole column set. The same pass fixes the edge-loading assertion,
   which still expected the old single spinner cell and tripped Playwright's strict mode against
   the four skeleton rows (now `.First`).
6. **`SortButton_SortedColumn_HoverFocus`:** the Tab walk budget (40) was exhausted before the
   ergonomics table because the demo page grew in phases 12–13; the walk now allows 250 presses
   (the walk stops at the first sort button it reaches).
7. **`DataTable_Axe` dark color-contrast:** two fixes — the dark switch now waits out the demo
   layout's 300 ms colour transition before scanning (a mid-fade scan flagged toolbar/cell text),
   and the axe failure message now prints each offending element's class/text/computed colours.
   The remaining genuine violation (the unstyled export dropdown trigger span in dark) is fixed
   by the tokenized trigger styling (`tm-dropdown-trigger` gets theme text/surface tokens).
